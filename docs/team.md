# Работа четырёх участников

| Направление | Папки | Результат |
| --- | --- | --- |
| Backend и доступность | `backend/`, `scripts/` | Стабильный API, очередь, запуск и URL |
| Frontend | `frontend/` | Загрузка, статус, события и исходные кадры |
| ML / GPU | `inference/`, `models/README.md` | Реальный локальный анализатор и измерения |
| Данные / нормы / QA | `rules/`, `docs/`, тесты | Условия категорий, исключения, проверка ошибок |

Участников владелец добавляет самостоятельно в Settings → Collaborators.

## Минимальный рабочий процесс

```bash
git clone https://github.com/gojosatorukz/forte-cash-monitor.git
cd forte-cash-monitor
git switch -c feat/short-task-name
# Изменения, локальная проверка, затем:
git add path/to/changed/files
git commit -m "Describe the concrete change"
git push -u origin feat/short-task-name
```

Создать pull request в `main`, дождаться CI и проверить сквозной сценарий.
Не копировать свой `.env` или датасет в PR. Ключи не отправлять в issue/комментарий.
Для документации команды использовать файлы `docs/`.

## Первые контрольные точки

1. До конца первых двух часов реализации выбрать проверенный runtime на Mac/GPU
   и проверить возможный публичный входящий доступ.
2. Подключить `inference.base.Analyzer` к API без изменения контракта жюри.
3. Разделить копии и близкие сцены при оценке, снять новые углы.
4. К последним трём часам остановить добавление функций и проверять сдачу.

Пока нет реального анализатора, инфраструктурные тесты используют синтетические
объекты. Их прохождение не является оценкой качества ML.
