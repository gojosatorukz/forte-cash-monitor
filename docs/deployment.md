# Репозиторий, работающий сервис и сдача

## Что сдаётся по кейсу

Разделы 8 и 10 «Кейс_ForteBank.docx» требуют:

1. Публичный URL работающего интерфейса.
2. Адрес API и ключ для заголовка `X-API-Key`.
3. Инструкцию запуска/использования.
4. Архитектуру, модели, источники правил, категории и ограничения.

Жюри загружает тестовые записи удалённо через API. Если сервис недоступен или
не вернул результат за пять минут, видео считается необработанным.
Наличие подробного README не заменяет работающий публичный сервис.
Дополнительные поля формы сдачи нужно проверить у организаторов.

## Вариант A: Mac с 16 ГБ на площадке

API и локальная MLX-модель запускаются на ноутбуке. ПК после экспериментов/обучения
не нужен. На время проверки нужны питание, отключённый сон и устойчивый сетевой доступ.
Скорость полного анализа должна быть измерена заранее, включая два запроса одновременно.

## Вариант B: ПК с RTX 5080 в офисе

Сервис работает на офисном ПК, ноутбук используется как клиент через браузер.
ПК не обязан находиться в здании хакатона, но остаётся включённым и достижимым
до завершения проверки. Проверить офисный firewall, роутер, CGNAT и допустимый
входящий HTTPS-доступ. Проверять из внешней сети, например с мобильного интернета.

## Вариант C: хостинг Python / арендованный сервер

Технически Python можно размещать на Render или Railway; существуют и GPU-платформы,
например Runpod. Это облачная инфраструктура, а не физически локальный компьютер команды.

В разделе 7 ТЗ запрещены внешние AI API и требуется исполнение всех моделей внутри
развёрнутого командой сервиса. При этом FAQ содержит более широкую формулировку
о дисквалификации за «облачные решения по API». Поэтому самостоятельное размещение
весов на арендованном GPU и способ передачи тестовых видео через сторонний шлюз
нужно явно уточнить у организаторов. Нельзя автоматически считать этот вариант
разрешённым или равнозначным собственному ноутбуку.

Текст вопроса для организаторов (команда отправляет самостоятельно):

> Разрешён ли сервер, арендованный командой, на котором все скачанные open-source
> модели выполняются самостоятельно, без вызовов внешних AI API? Разрешён ли
> HTTPS-туннель до нашего ноутбука/ПК для доступа жюри к интерфейсу и API?

До ответа базовый план — своё оборудование. Размещение на платном хостинге в этой
версии не выполнено; подписки и расходы не создавались.

## Что уже можно запускать

```bash
python scripts/run.py
```

Это локальный режим 127.0.0.1. `--host 0.0.0.0` открывает прослушивание сетевых
интерфейсов, но само по себе не создаёт публичный URL, HTTPS и маршрутизацию из интернета.
Публичный интерфейс и защищённый API можно открыть до подключения модели.
Готовность анализа проверяется отдельно через `/readyz`; до подключения модель не даёт вердикты.

Ссылка на GitHub не является ссылкой на запущенный сервис. GitHub Pages поддерживает
статические файлы; Python-сервер и GPU на нём не запускаются.

Официальные технические источники:

- https://render.com/docs/deploy-fastapi
- https://docs.railway.com/guides/fastapi
- https://docs.runpod.io/pods/overview
- https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages

## Настроенный способ предварительного доступа: Quick Tunnel

Команды из README поднимают исходящее соединение `cloudflared` к Cloudflare. Входящие
порты роутера не открываются; Uvicorn продолжает слушать только `127.0.0.1:8000`.
Сайт и API используют один публичный HTTPS origin, включая обязательные пути ТЗ.
Плата, домен и аккаунт для Quick Tunnel не нужны.

Установщик скачивает фиксированный релиз `2026.10.1` из официального репозитория Cloudflare,
сверяет SHA-256 с метаданными релиза и сохраняет бинарник только в игнорируемую `.runtime/bin/`.
На Mac с Apple Silicon используется Darwin arm64. Установщик также выбирает Linux
amd64/arm64 и Windows amd64, но запуск в этой работе проверен только на macOS arm64.

Запуск:

```bash
python scripts/install_tunnel.py
python scripts/run.py
# В другом терминале:
python scripts/public_link.py --handoff-dir ../output/submission
```

Не запускать второй `scripts/run.py`, если порт уже обслуживается текущим процессом.
Для подключения модели остановить и перезапустить только Python-сервис. Туннель
сохраняется, и внешний URL остаётся тем же. Активные анализы при перезапуске прервутся.

`public_link.py`:

- Публикует только выбранный локальный порт; другие папки и порты не проксируются.
- Проверяет `/healthz` перед стартом и защищает от случайного второго запуска.
- Пишет технический лог в `.runtime/public-link.log`, адрес — в `.runtime/public-link.json`.
- Создаёт отдельный файл доступа с API-ключом; на POSIX права файла — `0600`.
- На macOS запускает `caffeinate -i` на время туннеля, предотвращая простойный сон.
  Закрытие крышки, выключение, отсутствие питания или интернета этим не исправляются.
- При `Ctrl+C` завершает собственный `cloudflared` и процесс предотвращения сна.

На Windows права доступа регулируются ACL пользователя, а не POSIX-режимом `0600`.
Файл с ключом должен храниться в закрытой папке пользователя.

## Ограничения временного адреса

Quick Tunnel меняет hostname при новом запуске, не даёт гарантии доступности, ограничивает
число одновременных запросов (200) и не поддерживает SSE. Наш API использует обычный опрос.
Интерактивную авторизацию Cloudflare Access или email-PIN перед API не включать: жюри
нужен автоматический запрос с `X-API-Key` без входа в браузере.

Для стабильного hostname нужен постоянный Cloudflare Tunnel с собственным доменом либо
другой согласованный хост. Адрес нельзя переносить между компьютерами вместе с Git-кодом.
Если модель будет работать на другом ноутбуке/офисном ПК, финальный туннель следует
запустить там и обновить данные сдачи. Доступность любого варианта зависит от работающего
компьютера и сети; публичный URL не переносит вычисления на сервер Cloudflare.

Cloudflare завершает внешнее TLS-соединение и пересылает запрос на origin по зашифрованному
туннелю. Через него проходят заголовки, включая API-ключ, видео и ответы. Перед работой
с закрытыми тестовыми данными организаторы должны подтвердить допустимость этого маршрута.
В текущей проверке видео датасета наружу не отправляются.

## Проверка перед сдачей

Публичные `/`, `/docs`, `/openapi.json`, `/healthz` должны отвечать 200. `/readyz` — 503,
пока модели нет, затем 200. Запросы к обязательным API-путям без ключа — 401.
Локальные `.env`, `.git/` и `.runtime/` не обслуживаются HTTP-сервисом. `robots.txt`
и `X-Robots-Tag` запрещают поисковую индексацию прототипа, но не являются защитой доступа.

После согласования маршрута и подключения модели выполнить из внешней сети:

```bash
python scripts/smoke_test.py --base-url https://YOUR-HOST.trycloudflare.com --video /path/video.mov
```

Команда передаёт настоящий ключ из `.env` через Cloudflare. Запускать её только при
разрешённом использовании этого посредника и явном согласии владельца ключа.
Проверить также длинное видео, два одновременных запроса, время и соответствие кадров.
До этого публичная доступность интерфейса не означает готовность AI-анализа для зачёта.

Официальные источники:

- https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/
- https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/
- https://github.com/cloudflare/cloudflared/releases/tag/2026.10.1

После подключения модели обновить статус в локальном файле доступа без перезапуска туннеля:

```bash
python scripts/public_link.py --refresh-access --handoff-dir ../output/submission
```

Эта команда обращается только к локальному сервису и записывает файл с ключом на диск;
внешний запрос с ключом она не выполняет.
