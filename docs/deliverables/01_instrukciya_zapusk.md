# 1. Инструкция по запуску и использованию

> Сервис «Контроль кассовой дисциплины» принимает видео из кассового помещения (`.mov` / `.mp4`) и возвращает:
> - вердикт: `violation` / `no_violation`;
> - список нарушений с таймкодом и описанием на русском;
> - 1–3 кадра-доказательства (с рамками и подписями ролей людей, один кадр — без разметки для сравнения) и короткий видеофрагмент на каждое нарушение;
> - ссылку на пункт нормативного акта РК.
>
> Всё работает **локально**: облачных AI API нет, видео не покидает машину. Распознавания лиц нет, звук не используется.

## 1.1. Требования

| Компонент | Требование |
|---|---|
| ОС | Linux (целевая машина: Ubuntu 22.04; разработка: Linux) |
| GPU | NVIDIA с CUDA ≥ 12.8 (целевая машина: RTX 5080 16 ГБ; разработка велась на RTX 3060 6 ГБ) |
| ПО | Python 3.12, [`uv`](https://docs.astral.sh/uv/), `ffmpeg` / `ffprobe` |
| Сеть | Нужна только при первой загрузке весов моделей, дальше сервис работает офлайн |
| Публичный доступ | https://forte.incode.kz: Caddy на сервере команды + обратный SSH-туннель к машине сервиса (см. 1.2) |

## 1.2. Установка и запуск

```bash
git clone <TODO: URL репозитория> forte && cd forte/service
cp .env.example .env          # задать свой API_KEY, при необходимости PORT
API_KEY=<API_KEY> ./run.sh   # uv sync + uvicorn на 0.0.0.0:8000
```

Сервис стартует сразу, а модели анализатора загружаются в фоне. Задачи можно отправлять сразу: они ждут в очереди.
Готовность проверяется так:

```bash
curl -s http://localhost:8000/healthz
# {"ok": true, "analyzer_ready": true, "analyzer_error": null}
```

Публичную ссылку отдавайте только после `"analyzer_ready": true`, иначе загрузка моделей съест бюджет первых задач.

**Модели (VLM-сервер).** llama.cpp `llama-server` b11707 с Qwen3-VL-4B-Instruct Q4_K_M + mmproj F16 слушает `127.0.0.1:8090`
(`--image-min-tokens 1024`). На целевой машине он работает как пользовательская служба `forte-vlm` (`systemctl --user status forte-vlm`).
Веса детекторов (RT-DETRv2, OWLv2) скачиваются один раз (`scripts/fetch_models.py`, ~0,7 ГБ); после этого сервис стартует офлайн
(`HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, `UV_OFFLINE=1`).

**Подключение детектора.** Анализатор выбирается переменной `ANALYZER=<модуль>:<Класс>`. Для детектора:
`ANALYZER=forte_detector.service_adapter:ForteAnalyzer`, `RULES_PATH` указывает на `detector/taxonomy/rules.json`.
Без этой переменной работает заглушка `app.analyzers.stub:StubAnalyzer`.

**Развёртывание на целевой машине.** Docker там не используется: сервис и VLM запускаются через `uv` как пользовательские службы
`systemctl --user` с включённым linger, поэтому стартуют при загрузке без входа пользователя:

| Служба | Что делает |
|---|---|
| `forte-vlm` | llama-server с Qwen3-VL-4B на `127.0.0.1:8090` (стартует первой, чтобы VLM первой получила видеопамять) |
| `forte-service` | FastAPI-сервис с детектором (`run.sh`, переменные из `~/forte/.env`) |
| `forte-relay` | обратный SSH-туннель к серверу команды для https://forte.incode.kz |

У всех `Restart=always`: после аварийной остановки служба поднимается за 3–6 с. После перезагрузки машины сервис
полностью готов примерно через 42 с после включения питания.

```bash
systemctl --user status forte-vlm forte-service forte-relay
journalctl --user -u forte-service -f
```

### Публичный URL

Публичный адрес сервиса: **https://forte.incode.kz** (веб-интерфейс и API). Поле `public_url` в ответе `GET /healthz`
показывает этот же адрес.

Как устроена публикация:

```
жюри ──HTTPS──▶ forte.incode.kz (сервер команды: Caddy, автоматический TLS)
                   └─ обратный SSH-туннель ─▶ машина сервиса (RTX 5080) 127.0.0.1:8000
```

- DNS-запись `forte.incode.kz` указывает на сервер команды. Caddy на нём принимает HTTPS и передаёт запросы в обратный
  SSH-туннель, который машина сервиса сама держит открытым. На машине сервиса не нужны публичный IP и проброс портов.
- Туннель — отдельная служба: перезапуск самого сервиса адрес не меняет.
- На сервере команды **нет анализа и моделей**: он только пробрасывает HTTPS-запросы. Видео обрабатывается на машине сервиса.
- Запасной вариант на случай отказа сервера команды: Cloudflare quick tunnel (`scripts/tunnel.sh`) с временным адресом
  `https://<случайные-слова>.trycloudflare.com`; адрес меняется при каждом перезапуске.

```bash
curl -s http://localhost:8000/healthz       # на машине сервиса: {"ok": true, "analyzer_ready": true, ..., "public_url": "https://forte.incode.kz"}
curl -s https://forte.incode.kz/healthz     # проверка доступа снаружи
```

**Чек-лист на день проверки жюри:**
1. Отключить сон, гибернацию и автообновления ОС на машине сервиса.
2. Дождаться `"analyzer_ready": true` и только после этого сдавать URL.
3. Проверить снаружи: `POST /api/v1/analyze` с `X-API-Key` на коротком видео и `GET /api/v1/jobs/{id}` до `done`.
4. **После сдачи URL не перезапускать туннель, Caddy и сервис без необходимости:** на время перезапуска сервис недоступен.

## 1.3. Веб-интерфейс

Откройте https://forte.incode.kz (локально: `http://localhost:8000/`):

1. **Загрузка.** Перетащите или выберите видеофайл. Пока файл загружается, отображается прогресс.
2. **Анализ.** Отображаются текущий этап и прогресс обработки.
3. **Результат:**
   - баннер с вердиктом «Нарушение обнаружено» / «Нарушений не обнаружено»;
   - видеоплеер с метками нарушений на таймлайне; клик по таймкоду перематывает видео;
   - карточка каждого нарушения: код и тип, интервал (клик перематывает запись), «Уверенность в факте» и «Сила правовой нормы»,
     описание («Наблюдение… Норма…»), видеофрагмент события, кадры-доказательства (с рамками «кассир» / «посетитель» и бейджем «Разметка»; открываются в увеличенном виде),
     блок «Нарушенная норма» с дословной цитатой и ссылкой на adilet.zan.kz. Для T99 — «Норма не определена — требуется проверка специалистом».
4. **История проверок** и ссылки вида `#job=<id>`, чтобы поделиться результатом.
5. **«Нормативная база»** — окно со всеми типами нарушений и источниками.

Веб-интерфейсу ключ не нужен: он использует внутренние маршруты `/ui-api/*`. API для автоматической проверки защищён ключом.

## 1.4. REST API

Все запросы к `/api/v1/*` требуют заголовок `X-API-Key`. Без ключа или с неверным ключом сервер отвечает `401`.

### Отправить видео на анализ

```bash
curl -s -X POST "https://forte.incode.kz/api/v1/analyze" \
  -H "X-API-Key: <API_KEY>" \
  -F "file=@Х-17.mov"
```
Ответ:
```json
{"job_id": "3f2a…", "status": "processing"}
```
Ошибки: `400` пустой файл, `401` нет ключа или ключ неверный, `413` файл больше `MAX_UPLOAD_MB`.

### Получить результат

```bash
curl -s "https://forte.incode.kz/api/v1/jobs/3f2a…" -H "X-API-Key: <API_KEY>"
```

Пока идёт обработка, `status` равен `processing`. Опрашивайте раз в 2–5 с. Итог: `done` или `failed`.

Чистое видео (X-43) возвращает `"verdict": "no_violation"` и `"violations": []`; анализ занял 10 с.

**Поля.** Обязательные по кейсу: `job_id`, `status`, `verdict`, `violations[].type`, `timecode_sec`, `description`,
`evidence_frames[].timestamp_sec`, `image_base64` (JPEG). Дополнительные поля служат для интерфейса и проверки человеком:

| Поле | Значение |
|---|---|
| `type_id`, `title_ru` | Код типа (T1…T15, T99) и его название; `type` совпадает с `title_ru` |
| `start_sec`, `end_sec` | Интервал события; `timecode_sec` — опорный момент внутри него |
| `fact_conf` (= `confidence`) | Уверенность, что факт виден на записи, 0..1 |
| `legal_conf`, `legal_strength` | Сила связи с нормой: **порядковая шкала**, а не вероятность (`high` → 0,9, `medium` → 0,7, `low` → 0,4); категория — в `legal_strength` |
| `rule`, `rules` | Основная норма и список всех норм типа из справочника: документ, пункт, дословная цитата, ссылка на adilet |
| `evidence_frames[].boxes`, `.annotated` | Рамки людей на кадре и признак, что рамки нарисованы на изображении (см. ниже) |
| `clip_url` | Видеофрагмент события (см. ниже) |
| `partial`, `warnings` | Частичный результат при нехватке времени; предупреждения обработки |
| `video_meta`, `meta.analyzer` | Параметры видео; служебные данные анализатора (время, число вызовов VLM) |

**Доказательства.**
- **Видеофрагмент.** Для каждого нарушения сервис вырезает MP4 (H.264) вокруг события (±2 с, не длиннее 8 с; для X-17 — 8,0 с).
  Путь в `clip_url` относительный: `GET https://forte.incode.kz/api/v1/jobs/{id}/clips/{n}.mp4` с тем же `X-API-Key`.
  В интерфейсе плеер в карточке нарушения. Рамки на видеофрагмент не накладываются.
- **Рамки на кадрах.** Каждый кадр несёт `boxes: [{x, y, w, h, label, kind}]` (координаты нормированы 0..1).
  Кадры **с нарисованными рамками** помечены `annotated: true`: красные рамки с подписями ролей людей («кассир», «посетитель»).
  `evidence_frames[0]` — опорный момент с рамками, `[1]` — тот же момент без разметки, `[2]` — следующий опорный момент с рамками.
  Сейчас размечаются **только люди** (`kind: "person"`); рамки предметов и зон (деньги, дверь, сейф, экран) в разработке.
- Рамки обозначают только роль или область. Лица не распознаются.

**Нарушение без нормы (T99).** Для типа T99 «Иное подозрительное действие» сервис возвращает `"rule": null` и `"rules": []`,
а интерфейс показывает «Норма не определена — требуется проверка специалистом».

**Частичный результат.** Если анализ не уложился в бюджет, задача всё равно завершается со статусом `done`, флагом `"partial": true`
и всеми нарушениями, найденными к этому моменту. Пустой ответ из-за таймаута невозможен по построению.

### Пример: пакетная проверка папки

```bash
KEY=<API_KEY>; URL=https://forte.incode.kz
for f in videos/*.mov; do
  id=$(curl -s -X POST "$URL/api/v1/analyze" -H "X-API-Key: $KEY" -F "file=@$f" | python3 -c 'import sys,json;print(json.load(sys.stdin)["job_id"])')
  until s=$(curl -s "$URL/api/v1/jobs/$id" -H "X-API-Key: $KEY"); echo "$s" | grep -qv '"status": *"processing"'; do sleep 3; done
  echo "$f → $(echo "$s" | python3 -c 'import sys,json;d=json.load(sys.stdin);print(d["status"],d.get("verdict"),[v["type"] for v in d.get("violations",[])])')"
done
```
