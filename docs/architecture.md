# Архитектура и границы текущей версии

## Реализовано

Один процесс Uvicorn обслуживает локальные HTML/CSS/JS и API. SQLite хранит задачи
и ответы; загрузки находятся в `.runtime/uploads`. Доступ к задачам защищён одним
общим ключом команды, а не многопользовательской авторизацией.

При наличии анализатора один worker извлекает задачи по очереди. Синхронный анализ
выполняется в отдельном потоке, чтобы не блокировать HTTP event loop. При перезапуске
незавершённые задачи становятся `failed`, завершённые результаты остаются в SQLite.

Без анализатора `/readyz` и создание задачи отвечают 503. Это ожидаемое состояние основы.

`AnalysisResult` содержит только `verdict` и `violations` по схеме кейса.
Для события нужны тип, фактический таймкод, описание с нормативным основанием и 1–3 JPEG.
Схема отклоняет противоречивый вердикт, отрицательные/нечисловые времена и некорректные JPEG.
Проверку соответствия кадра событию, времени длительности видео и правовой связи
должен реализовать анализатор; форматная валидация это не доказывает.

## План анализа

1. Декодировать MOV с учётом поворота и реальных PTS.
2. Автоматически определить сцену и временные роли без распознавания лиц.
3. Проследить людей/объекты; дополнить кандидаты обзором всей записи.
4. Проверить последовательность нескольких кадров локальной VLM.
5. Применить локальный каталог условий и исключений.
6. Уточнить время и выбрать исходные JPEG, без дорисовки доказательств.

Исходные имена и таймкоды из обучающей таблицы не являются входными признаками модели.
Неизвестное условие нельзя превращать в подтверждённый факт.

## Ограничения основы, которые нужно закрыть до сдачи

- Нет реальной модели, декодера, автоматического извлечения кадров и проверки качества.
- Нет публичного HTTPS-доступа; сейчас слушается только 127.0.0.1.
- Ограничение загрузки в коде касается содержимого файла; публичный reverse proxy
  должен дополнительно ограничить весь запрос и время загрузки.
- Бюджет времени включает очередь. Анализатор обязан завершаться кооперативно;
  поток Python нельзя безопасно принудительно остановить. Жёсткая изоляция GPU-задачи
  и watchdog — отдельный этап после измерений.
- Сервис рассчитан на один Uvicorn worker. Несколько процессов потребуют другой
  схемы владения задачами и обработки перезапусков.
- Нет автоматической очистки исходных загрузок/результатов; согласовать срок хранения
  и очистку перед работой с тестовыми видео.
- HF offline flags относятся только к Hub. Финальный запуск требует проверки всего
  исходящего трафика анализатора, без внешних AI-запросов.

GitHub Actions проверяет только синтетические инфраструктурные тесты.
