# Архитектура сервиса

## Поток работы

```text
Браузер / жюри
      ↓ X-API-Key + MOV
FastAPI → UUID-загрузка → SQLite-очередь
      ↓ один worker, отдельный поток
Локальный Analyzer (предстоит подключить)
      ↓ AnalysisResult: тип, время, описание, 1–3 JPEG
Проверка схемы → SQLite → обязательный API ТЗ
                         ↘ плеер / история / JSON / автономный HTML
```

HTML/CSS/JS, справка и OpenAPI обслуживаются тем же процессом, без внешних ресурсов.
Модель один раз загружается локальной фабрикой `FCM_ANALYZER_FACTORY`. HTTP остаётся
доступным во время анализа. Модель не получает ключ или исходное имя файла.

## Контракт ML

Полный пример, ошибки и утилиты — [ml_integration.md](ml_integration.md).
`inference.base.AnalysisRequest` содержит путь, монотонный deadline и необязательный
`report_progress(stage)`. Анализатор возвращает `AnalysisResult`, без дополнительных полей.

Схема проверяет согласованность вердикта со списком событий, неотрицательные конечные
времена, 1–3 декодируемых JPEG на событие. Соответствие кадра событию, времени реальному
PTS и правового основания обстоятельствам должен проверить анализатор. Форматная
валидация не доказывает правильность ML.

## Надёжность и данные

- Ключ проверяется перед чтением multipart, а также указан в OpenAPI security scheme.
- Ограничены размер файла, поток тела запроса, время загрузки, размер очереди.
- Файлы получают UUID, `.part` убирается при ошибке; SQLite хранит статусы и результаты.
- Перезапуск помечает незавершённые задачи `failed`, сохраняя завершённые результаты.
- Отдельный watchdog отмечает просроченные задачи даже при зависшем потоке анализа.
  Завершённая ошибка не переписывается поздним результатом модели.
- Если поток превысил deadline, новые загрузки блокируются до его возврата; зависший
  навсегда поток требует перезапуска. Принудительной процессной изоляции пока нет.
- Очистка раз в минуту удаляет завершённые данные старше 24 часов (настраивается).
  Активный файл работающей модели сохраняется до возврата; скачанные отчёты вне сервера.
- API/видео/HTML получают `Cache-Control: no-store`, запрет встраивания и CSP.
  API-ключ браузер хранит только в памяти вкладки, без cookie/localStorage.
- Один общий ключ даёт доступ ко всем проверкам сервиса. Отдельных аккаунтов нет.

В сервисе не реализована обязательная транскодировка MOV: браузер воспроизводит
поддерживаемые им кодеки, иначе показывает предупреждение. Это не влияет на возможность
анализа через серверный декодер, который должен добавить ML-разработчик.

## До сдачи

1. Подключить реальный декодер/модель и проверить зависимость результата от содержания
   видео, без подстановок по имени, хешу и обучающим таймкодам.
2. Проверить автоматическую адаптацию к ракурсу, условия норм, исключения и доказательства.
3. Измерить полный путь на коротком/длинном видео и двух параллельных запросах.
4. Закрепить финальный публичный HTTPS и оборудование с моделью. Quick Tunnel уже можно
   использовать для предварительного доступа; маршрут закрытых видео согласовать с организаторами.
5. Проверить из другой сети загрузку, опрос, ответ, отсутствие внешних AI-вызовов.

Сервис запускается с **одним** Uvicorn worker. Запуск нескольких процессов требует другой
схемы владения задачами, моделью и перезапусками. Лимиты reverse proxy также нужны при
публикации. HF offline flags защищают только обращения Hub, а не весь сетевой трафик:
финальная проверка исходящих запросов модели обязательна.

Тесты CI проверяют синтетические транспортные сценарии, не качество выявления нарушений.
