# Подключение модели к Forte Cash Monitor

Инструкция для ML-разработчика и участника, который запускает сервис. Передайте рабочий
Python-модуль с локальными весами, зависимостями и измерениями на выбранном компьютере.
Мы подключаем его к существующим сайту, очереди и API. Отдельный HTTP-сервер модели для
этой схемы не требуется. Реальная модель пока не подключена; инструкция описывает передачу
и приёмку, а не подтверждает готовность анализа.

## Чей API и какой ключ нужен

У команды один внешний API сервиса: `POST /api/v1/analyze` принимает видео,
`GET /api/v1/jobs/{job_id}` возвращает результат. Сайт использует этот же API.
Его код уже находится в `backend/`. Владелец GitHub-аккаунта и автор модели на адрес
или работу API не влияют.

`X-API-Key` — наш собственный секрет для доступа к сервису. Сервер сравнивает заголовок
с `FCM_API_KEY` из своего локального `.env`. Это не ключ OpenAI, Hugging Face или банка.
ML-модуль вообще не получает этот ключ: он получает путь к локальному видео.

На другом компьютере `scripts/init_env.py` создаст другой случайный ключ. Для сдачи
нужны **адрес и ключ одного финального сервера**. Можно сохранить существующий ключ,
передав его владельцу сервера закрытым способом, или выдать новый и обновить инструкцию
для жюри и поле ключа на сайте. Публиковать `.env` или ключ в репозитории нельзя.

## Где запускать финальную систему

```text
Браузер или жюри
  -> публичный HTTPS адрес
  -> наш FastAPI на выбранном компьютере
  -> очередь -> LocalAnalyzer.analyze -> локальные модели и декодер
  -> события с реальными JPEG -> API, сайт и отчёт
```

Рекомендуем запускать весь сервис на том же компьютере, где проверена модель. Если
тиммейт использует CUDA на RTX 5080, переносим туда репозиторий и запускаем там сайт,
API и модель; твой Mac остаётся клиентом в браузере. CUDA-модель сама по себе на M1/M2
не заработает. Для финального Mac нужен отдельно проверенный вариант runtime и весов.
Скачивать модель на все ноутбуки команды не требуется.

Раздельная схема «бэкенд на одном компьютере, HTTP-сервер модели на другом» потребует
нового адаптера, передачи файлов и контроля сетевых сбоев. Текущая фабрика рассчитана
на локальный Python-вызов. Один URL модели без её кода и развёртывания не заменяет эту
интеграцию. Если отдельный сервер уже написан, передайте и его исходники и зависимости;
сначала согласуем способ подключения.

Финальный компьютер должен оставаться включённым, без сна и с интернетом на время
проверки. Cloudflare даёт маршрут к нему; вычисления остаются на компьютере команды.
При переносе на другой компьютер понадобится новый временный публичный адрес.

## Что ML разработчик передаёт команде

| Что передать | Что должно быть внутри |
| --- | --- |
| Ветка и commit SHA | `inference/local.py`, вспомогательные модули, локальные промпты и настройки; рабочий код, не только notebook |
| Фабрика анализатора | `create_analyzer()` возвращает объект с `name` и синхронным `analyze(request)` |
| Веса и файлы обработки | Точный ID и revision, локальная структура папок; tokenizer, processor, конфиги, дополнительные детекторы, если нужны |
| Установка окружения | Версия Python, точные зависимости, проверенная команда установки для CUDA или Mac, системные декодеры |
| Происхождение моделей | Лицензии, ссылки на исходники/веса и SHA-256 файлов; записать в `docs/models.md` |
| Возможности и ограничения | Поддерживаемые категории, проверенные исключения, неизвестные ракурсы и сценарии, которые пока не определяются |
| Реальные результаты | Короткое видео с событием и без события: JSON, проверенные таймкоды и исходные кадры; хранить вне Git |
| Измерения на финальном устройстве | Холодный запуск, короткий и длинный ролик, два одновременных запроса, peak RAM/VRAM, ошибки и версия кода |

Код передаётся через ветку, например `feature/local-inference`, и pull request в `main`.
Веса размещаются на финальном компьютере в `models/` вне Git или скачиваются заранее
по воспроизводимой инструкции. Видео и отчёты с кадрами также остаются вне Git.
Передавать секреты сторонних аккаунтов для инференса не нужно.

## Граница ответственности

| Сервис уже делает | Анализатор должен делать |
| --- | --- |
| Ключ, загрузка MOV, UUID, очередь и хранение | Декодировать реальное видео; проверить контейнер/кодек/длительность |
| HTTP-статусы и асинхронный опрос | Учесть поворот, исходные PTS, всю последовательность |
| Контроль срока задачи и безопасные ошибки | Найти события локальными моделями без вызовов внешних AI API |
| Проверка схемы, base64 и декодируемости JPEG | Выбрать 1–3 исходных кадра; не генерировать доказательства |
| Плеер, история, кадры, JSON и HTML-отчёт | Указать наблюдение, тип, время, основание и условия применения |

Исходное имя загруженного файла анализатору не передаётся: `video_path` содержит случайный
UUID. Не читать соседний датасет/таблицу меток при инференсе. Отсутствие модели, повреждённое
видео и ошибка исполнения должны завершаться ошибкой, а не `no_violation`.

## Контракт Python модуля

Создайте **свой** `inference/local.py`. Пример ниже — схема, вызовы `decode`, `pipeline`
и `load_local_models` нужно заменить реальным кодом; готового анализатора в репозитории нет.

```python
from backend.app.schemas import AnalysisResult
from inference.base import AnalysisRequest
from inference.helpers import check_deadline, validate_timestamps


class LocalAnalyzer:
    name = "название-модели-и-версии"

    def __init__(self):
        self.models = load_local_models()  # один раз; только локальные файлы

    def analyze(self, request: AnalysisRequest) -> AnalysisResult:
        check_deadline(request)
        request.report_progress("decoding")
        video = decode(request.video_path)  # учесть ориентацию, реальные PTS
        request.report_progress("scanning")
        observations = pipeline(video, self.models, request.deadline_monotonic)
        check_deadline(request)  # проверять также внутри циклов, до/после генерации
        request.report_progress("verifying")
        # Проверить условия, исключения, время и связь с нормой.
        request.report_progress("evidence")
        result = AnalysisResult.model_validate(observations)
        return validate_timestamps(result, video.duration_sec)


def create_analyzer():
    return LocalAnalyzer()
```

`request` неизменяемый; его поля:

- `video_path: Path` — локальная запись;
- `deadline_monotonic: float` — абсолютный срок по `time.monotonic()`, с учётом очереди;
- `report_progress(stage)` — необязательные сообщения об этапах. Допустимы `decoding`,
  `scanning`, `verifying`, `evidence`. Не передавайте произвольные проценты или текст модели.

Фабрика загружает веса, декодер и необходимые настройки один раз на процесс. Сделайте
проверку нужного устройства и прогрев, чтобы ошибка не обнаружилась только на первом
видео жюри. `analyze` вызывается сервисом в фоновом Python-потоке: проверять нужно именно
этот путь, а не только запуск в notebook. Не делать `analyze` функцией `async def`.

Используйте пути от корня проекта или явно заданного каталога, а не абсолютный путь
чужого ноутбука. `FCM_MODELS_DIR` в `.env.example` — заготовка: текущий `Settings` сервиса
не читает это поле и не передаёт его модели автоматически. ML-модуль должен сам явно
прочитать свой конфиг, в том числе `.env`, если он нужен, и разрешить путь к весам.
Простое `os.getenv()` не читает произвольные строки файла `.env`.

До старта скачайте все нужные файлы. Сервис устанавливает `HF_HUB_OFFLINE=1` и отключает
телеметрию Hub, но это не сетевой firewall. В загрузчиках используйте локальные пути
и режим вроде `local_files_only=True`, если runtime его поддерживает. Не загружать веса
на первом запросе и не вызывать внешние AI API.

## Что возвращает модель

Модель возвращает `AnalysisResult` или словарь, проходящий его проверку. Поля `job_id`
и `status` добавляет бэкенд; модель их не формирует. Отдельный обычный текст от VLM нужно
сначала разобрать, проверить и привести к этому результату.

```python
AnalysisResult(
    verdict="violation",
    violations=[
        {
            "type": "Название наблюдаемого сценария",
            "timecode_sec": actual_time,
            "description": (
                "Что видно до/во время/после события. Почему правило применимо. "
                "Документ РК, пункт, точная ссылка. Ограничения и проверенные исключения."
            ),
            "evidence_frames": [jpeg_evidence(source_image, actual_pts)],
        }
    ],
)
```

`jpeg_evidence` импортируется из `inference.helpers`. При `no_violation` список должен быть
пустым. Это утверждение об анализированной записи, а не запасной ответ при сбое.

```python
AnalysisResult(verdict="no_violation", violations=[])
```

Для каждого события нужны 1–3 настоящих кадра декодированного видео. `actual_time`,
`actual_pts` и `source_image` в примере выше берутся из этого видео. Время в секундах
от начала записи; если исходные PTS начинаются не с нуля, приведите их к единой шкале
плеера. Учтите поворот MOV и переменную частоту кадров. Нельзя заменить PTS номером
кадра, временем уменьшенного клипа или выдуманным таймкодом. Для проверки события
можно использовать кроп, но доказательство должно сохранять понятный исходный контекст.

`image_base64` содержит только base64 настоящего JPEG, без `data:image/...` и без пути
к файлу. Один JPEG — до 8 MiB и 20 млн пикселей; `type` — до 180 символов,
`description` — до 5000. Времена конечные, неотрицательные и не дальше конца записи.
`validate_timestamps` проверяет предел длительности, но не доказывает соответствие
картинки указанному времени: это проверяет ML-разработчик по декодеру.
Отдельных полей `confidence`, `law`, `bbox` в обязательном ответе ТЗ нет: не добавляйте их
в текущую строгую схему. Правовое основание входит в `description`. Для дополнительных
внутренних данных нужно отдельно согласовать расширение, сохраняя ответ жюри.

Каталог `rules/catalog.json` пока содержит **два подготовленных основания**. Он не подставляется
автоматически по имени типа и не доказывает поддержку категории моделью. Расширять только
после проверки нормы, её условий и исключений; не назначать штраф по одному кадру.
В `description` указывайте наблюдаемые действия и последовательность, условие применения
правила, документ РК, пункт и ссылку. Ненаблюдаемое право доступа или содержимое сумки
нельзя выдавать за установленный факт. Ошибка структурирования ответа не означает
отсутствие нарушения. Не считать неизвестный сценарий нормальным только потому, что он
не вошёл в несколько заранее написанных детекторов; отдельно измерить покрытие и ошибки.

## Ошибки и бюджет времени

Для ожидаемой ошибки используйте:

```python
raise AnalysisFailure("invalid_video")  # нет корректной видеодорожки
raise AnalysisFailure("unsupported_codec")  # декодер не поддерживает кодек
raise AnalysisFailure("deadline_exceeded")  # срок истёк
```

Другие исключения превращаются в `failed / analysis_failed`; их внутренний текст клиенту
не возвращается. Не записывайте ключи в логи. Заголовок `X-API-Key` модель не получает.

Сервис отмечает просроченные задачи как `failed` отдельным watchdog, даже если поток модели
завис. Новые загрузки блокируются, пока этот поток не вернётся. Python-поток **не прерывается
принудительно**: если библиотека зависла навсегда, нужен перезапуск процесса. Проверяйте срок
внутри циклов и задавайте ограничение генерации. Для жёсткого прекращения GPU-операции
нужна отдельная процессная изоляция; в текущей версии её нет.

По умолчанию бюджет — 270 секунд от начала POST, включая загрузку и очередь. Измерьте короткий и длинный ролик,
а затем два одновременных запроса: второй тратит часть срока в очереди. Очередь по умолчанию
вмещает четыре активных задачи, но это не обещание обработки всех четырёх за пять минут.
До тяжёлого этапа вычисляйте оставшееся время через `time.monotonic()` и ограничивайте
число кадров, кандидатов и токенов. По истечении срока возвращать частичный вердикт нельзя.
Бэкенд не умеет автоматически выбирать другую модель или устройство.

## Как установить на финальном компьютере

Ниже команды для нового клона на macOS или Linux. На текущем рабочем Mac не создавайте
заново окружение, не перезаписывайте `.env` и не запускайте второй сервер на порту 8000.

```bash
git clone https://github.com/gojosatorukz/forte-cash-monitor.git
cd forte-cash-monitor
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.lock.txt
python -m pip install --no-deps -e .
```

Используйте Python 3.12, на котором проверен сервис, либо проверенную совместимую версию
3.11+. Для Windows: `py -3.12 -m venv .venv`, затем `.venv\Scripts\Activate.ps1`.
Остальные команды `python` те же. CUDA, драйвер и ML-runtime должны соответствовать
проверенной инструкции тиммейта; базовый файл зависимостей сервиса их не устанавливает.

После слияния ML-ветки установите переданный файл зависимостей модели, например
`requirements-ml.lock.txt`. **Сейчас этого файла в репозитории нет**; имя и рабочую команду
установки передаёт ML-разработчик. Для разных GPU/Mac runtime могут понадобиться разные
файлы. Затем выполните `python -m pip check`, разместите веса в согласованном каталоге
и проверьте их контрольные суммы. Установка библиотек не скачивает веса автоматически.

Создайте локальный конфиг:

```bash
python scripts/init_env.py
```

В `.env` замените существующую пустую строку `FCM_ANALYZER_FACTORY=`, сохранив API-ключ:

```dotenv
FCM_ANALYZER_FACTORY=inference.local:create_analyzer
```

Затем запустите сервис из корня репозитория:

```bash
python scripts/run.py
```

Если сервер уже работает, сначала остановите именно его в терминале через `Ctrl+C`,
а затем запустите снова. Перезапуск прерывает текущие анализы. На текущем Mac оставьте
терминал туннеля работающим: перезапуск только Python сохраняет публичный URL.
Один worker обслуживает задачи последовательно; не добавлять `--workers 2` или `--reload`
на финальном запуске. Если фабрика не импортируется или веса не загружаются, сервер
не запустится; исправьте ошибку, а не заменяйте результат заглушкой.

## Как принять подключение

1. Откройте `http://127.0.0.1:8000/healthz`: HTTP 200 подтверждает только запуск сервера.
2. Откройте `http://127.0.0.1:8000/readyz`: нужен HTTP 200 и `ready: true`. Это проверка
   наличия анализатора без зависшей задачи, а не оценка точности ML.
3. На сайте введите ключ из `.env` **этого** сервера, загрузите разрешённое локальное MOV.
   Дождитесь результата, проверьте события, переход по времени, JPEG и JSON/HTML-отчёт.
4. Запустите проверку того же сервера через API:

```bash
python scripts/smoke_test.py --video /absolute/path/to/video.mov
```

Скрипт читает ключ из локального `.env`, не печатает его, опрашивает настоящий сервис и
проверяет ответ по схеме. Результат не доказывает правильность события — это проверяется
по исходным кадрам, меткам и контрольным записям отдельно.

До сдачи проверить положительную и отрицательную записи, длинный ролик, новый ракурс,
два запроса одновременно и испорченный MOV. При сбое последнего ожидается `failed`,
без итогового вердикта. Проверить 401 без ключа и с неправильным ключом. Для качества
сопоставить факты, время, кадры и норму вручную, записать FP/FN и время ответа; дубликаты
и близкие сцены держать в одной группе оценки. Не обещать точность по двум примерам.

## Как открыть анализ жюри

На финальном компьютере, где модель уже прошла локальную проверку:

```bash
python scripts/install_tunnel.py
# В другом терминале, при уже работающем scripts/run.py:
python scripts/public_link.py --handoff-dir ../output/submission
```

Не запускайте второй туннель на текущем Mac, если используете уже открытый адрес.
После подключения модели на нём обновите файл доступа без замены адреса:

```bash
python scripts/public_link.py --refresh-access --handoff-dir ../output/submission
```

Скрипт создаёт закрытый файл `Доступ_для_жюри.txt` с адресами и ключом. На другом
компьютере и ключ, и временная ссылка могут отличаться. Финальный комплект для жюри:
URL сайта, базовый URL API, `X-API-Key`, инструкция и ограничения. GitHub хранит исходники;
жюри обращается к запущенному сервису. Сайт менять для нового адреса не нужно: он
обращается к API своего же адреса.

Туннель передаёт HTTP-запросы через Cloudflare, включая ключ, загруженное видео и ответ.
Допустимость такого маршрута для закрытых тестовых данных нужно подтвердить у
организаторов; подробности и формулировка вопроса — в `docs/deployment.md`.
После согласования маршрута проверьте из внешней сети на разрешённой тестовой записи:

```bash
python scripts/smoke_test.py \
  --base-url https://YOUR-HOST.trycloudflare.com \
  --video /absolute/path/to/allowed.mov
```

Здесь `.env` тестового клиента должен содержать ключ финального сервера; скрипт отправит
его и выбранное видео через указанный адрес. Не отправляйте датасет автоматически
при обычной проверке доступности. Полный анализ через публичный адрес пока не проверен.

## Если подключение не работает

| Симптом | Что проверить |
| --- | --- |
| `/healthz` не открывается | Сервер запущен, порт 8000 свободен; ошибки импорта, зависимостей и загрузки весов в терминале |
| `/readyz` возвращает `analyzer_not_configured` | Строка фабрики в `.env`, нужный каталог проекта и перезапуск Python |
| 401 | Ключ от этого сервера, правильный заголовок; после переноса обновить ключ на сайте и у жюри |
| `analysis_failed` | Локальный лог: схема, JSON VLM, память, пути, JPEG; не заменять ошибку `no_violation` |
| `deadline_exceeded` или `analyzer_stalled` | Реальный остаток времени, очередь, ограничения генерации; зависший поток требует восстановления или перезапуска |
| Сайт открыт, загрузка даёт 503 | Доступность сайта и наличие модели проверяются отдельно через `/readyz` |
| На CUDA работает, на Mac нет | Нужен совместимый runtime; проще перенести весь сервис на проверенный компьютер |

Приёмка завершена, когда **один и тот же реальный анализатор** отвечает сайту и API,
возвращает проверяемые исходные кадры и укладывается в срок на выбранном оборудовании.
Прохождение инфраструктурных тестов само по себе этого не доказывает.
