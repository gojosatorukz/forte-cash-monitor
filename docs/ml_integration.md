# Подключение локального анализатора

Этот файл можно сразу передать разработчику модели. Он не должен переписывать HTTP API,
очередь, интерфейс или экспорт. Реализуется только модуль внутри `inference/`.

## Граница ответственности

| Сервис уже делает | Анализатор должен делать |
| --- | --- |
| Ключ, загрузка MOV, UUID, очередь и хранение | Декодировать реальное видео; проверить контейнер/кодек/длительность |
| HTTP-статусы и асинхронный опрос | Учесть поворот, исходные PTS, всю последовательность |
| Контроль срока задачи и безопасные ошибки | Найти события локальными моделями без вызовов внешних AI API |
| Проверка схемы, base64 и декодируемости JPEG | Выбрать 1–3 исходных кадра; не генерировать доказательства |
| Плеер, история, кадры, JSON и HTML-отчёт | Указать наблюдение, тип, время, основание и условия применения |

Исходное имя загруженного файла анализатору не передаётся: `video_path` содержит случайный
UUID. Не читать соседний датасет/таблицу меток при инференсе. Отсутствие модели, повреждённое
видео и ошибка исполнения должны завершаться ошибкой, а не `no_violation`.

## Минимальная интеграция

Создайте **свой** `inference/local.py`. Пример ниже — схема, вызовы `decode`, `pipeline`
и `load_local_models` нужно заменить реальным кодом; готового анализатора в репозитории нет.

```python
from backend.app.schemas import AnalysisResult
from inference.base import AnalysisFailure, AnalysisRequest
from inference.helpers import check_deadline, validate_timestamps


class LocalAnalyzer:
    name = "название-модели-и-версии"

    def __init__(self):
        self.models = load_local_models()  # загрузить веса один раз, только с диска

    def analyze(self, request: AnalysisRequest) -> AnalysisResult:
        check_deadline(request)
        request.report_progress("decoding")
        video = decode(request.video_path)  # учесть ориентацию, реальные PTS
        request.report_progress("scanning")
        observations = pipeline(video, self.models, request.deadline_monotonic)
        check_deadline(request)  # проверять также внутри циклов, до/после генерации
        request.report_progress("verifying")
        # Проверка условий/исключений, точного времени, связи с нормой.
        request.report_progress("evidence")
        result = AnalysisResult.model_validate(observations)
        return validate_timestamps(result, video.duration_sec)


def create_analyzer():
    return LocalAnalyzer()
```

`request` неизменяемый; его поля:

- `video_path: Path` — локальная запись;
- `deadline_monotonic: float` — абсолютный срок по `time.monotonic()`, с учётом очереди;
- `report_progress(stage)` — необязательные сообщения об этапах. Допустимы `decoding`,
  `scanning`, `verifying`, `evidence`. Не передавайте произвольные проценты или текст модели.

В локальном `.env`:

```dotenv
FCM_ANALYZER_FACTORY=inference.local:create_analyzer
```

Перезапустите `python scripts/run.py`. Фабрика запускается один раз на процесс. Если модель
не загрузилась, исправьте ошибку старта; не скрывайте её. `/readyz` должен вернуть HTTP 200
с `ready: true`. Один worker обслуживает задачи последовательно; `--workers 2` не использовать.

## Результат без дополнительных полей

```python
AnalysisResult(
    verdict="violation",
    violations=[
        {
            "type": "Название наблюдаемого сценария",
            "timecode_sec": actual_time,
            "description": (
                "Что видно до/во время/после события. Почему правило применимо. "
                "Документ РК, пункт, точная ссылка. Ограничения и проверенные исключения."
            ),
            "evidence_frames": [jpeg_evidence(source_image, actual_pts)],
        }
    ],
)
```

`jpeg_evidence` импортируется из `inference.helpers`. При `no_violation` список должен быть
пустым. Это утверждение об анализированной записи, а не запасной ответ при сбое.
Отдельных полей `confidence`, `law`, `bbox` в обязательном ответе ТЗ нет: не добавляйте их
в текущую строгую схему. Правовое основание входит в `description`. Для дополнительных
внутренних данных нужно отдельно согласовать расширение, сохраняя ответ жюри.

Каталог `rules/catalog.json` пока содержит **два подготовленных основания**. Он не подставляется
автоматически по имени типа и не доказывает поддержку категории моделью. Расширять только
после проверки нормы, её условий и исключений; не назначать штраф по одному кадру.

## Ошибки и время

Для ожидаемой ошибки используйте:

```python
raise AnalysisFailure("invalid_video")  # нет корректной видеодорожки
raise AnalysisFailure("unsupported_codec")  # декодер не поддерживает кодек
raise AnalysisFailure("deadline_exceeded")  # срок истёк
```

Другие исключения превращаются в `failed / analysis_failed`; их внутренний текст клиенту
не возвращается. Не записывайте ключи в логи. Заголовок `X-API-Key` модель не получает.

Сервис отмечает просроченные задачи как `failed` отдельным watchdog, даже если поток модели
завис. Новые загрузки блокируются, пока этот поток не вернётся. Python-поток **не прерывается
принудительно**: если библиотека зависла навсегда, нужен перезапуск процесса. Проверяйте срок
внутри циклов и задавайте ограничение генерации. Для жёсткого прекращения GPU-операции
нужна отдельная процессная изоляция; в текущей версии её нет.

По умолчанию бюджет — 270 секунд вместе с очередью. Измерьте короткий и длинный ролик,
а затем два одновременных запроса: второй тратит часть срока в очереди. Очередь по умолчанию
вмещает четыре активных задачи, но это не обещание обработки всех четырёх за пять минут.

## Проверить подключение

```bash
python scripts/smoke_test.py --video /absolute/path/to/video.mov
```

Скрипт читает ключ из локального `.env`, не печатает его, опрашивает настоящий сервис и
проверяет ответ по схеме. Результат не доказывает правильность события — это проверяется
по исходным кадрам, меткам и контрольным записям отдельно.

Работайте в своей ветке, например `feature/local-inference`. Фронт и бэк развиваются в
других папках; `inference/local.py` зарезервирован для интеграции модели.
