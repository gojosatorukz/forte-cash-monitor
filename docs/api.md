# API для жюри

Базовый URL локально: `http://127.0.0.1:8000`. Для сдачи заменить на публичный HTTPS URL.
Все `/api/v1/*` требуют заголовок `X-API-Key`. Значение берётся из локального `.env`.

## POST /api/v1/analyze

Multipart upload в поле `file`; `.mov`, до 64 MiB по умолчанию.
При готовом анализаторе успешный ответ HTTP 202:

```json
{"job_id":"3f2a9c1e-2338-4f74-b886-30f63edec541"}
```

Сейчас модель не подключена, поэтому ответ — 503.

## GET /api/v1/jobs/{job_id}

Обработка:

```json
{"job_id":"3f2a9c1e-2338-4f74-b886-30f63edec541","status":"processing"}
```

Результат без обнаруженных признаков:

```json
{"job_id":"3f2a9c1e-2338-4f74-b886-30f63edec541","status":"done","verdict":"no_violation","violations":[]}
```

При `violation` каждый элемент `violations` содержит:

- `type`: название наблюдаемого сценария;
- `timecode_sec`: время в секундах от начала видео;
- `description`: наблюдаемые факты, ограничение вывода, документ/пункт/ссылка;
- `evidence_frames`: от одного до трёх объектов с `timestamp_sec` и `image_base64`.

`image_base64` содержит непосредственно JPEG в base64, без префикса `data:image/...`.
В задаче `failed` нет `verdict`: возвращается объект `error` с кодом и безопасным сообщением.

## Ошибки

| Код | Смысл |
| --- | --- |
| 401 | Отсутствует или неверен API-ключ |
| 404 | Задача или исходный файл не найдены |
| 408 | Истекло время чтения загрузки |
| 413 | Содержимое файла больше лимита |
| 415 | Расширение файла отличается от MOV |
| 422 | Пустой файл или некорректная структура запроса/UUID |
| 429 | Очередь заполнена |
| 503 | Реальный локальный анализатор ещё не настроен |

`/healthz` подтверждает запуск HTTP-сервера. `/readyz` отдельно сообщает готовность модели.
Машиночитаемая спецификация: `/openapi.json`. Локальная справка: `/docs`.

## Дополнительный API рабочего кабинета

Эти методы также требуют `X-API-Key`, но не меняют два обязательных пути ТЗ.

| GET | Ответ |
| --- | --- |
| `/api/v1/service` | Готовность, имя анализатора, лимиты, число активных задач |
| `/api/v1/jobs?limit=10&offset=0` | `items`, `total`, `limit`, `offset`; без JPEG/base64 |
| `/api/v1/jobs/{id}/details` | `summary` (файл, этап, времена) и `result` (точный ответ ТЗ) |
| `/api/v1/jobs/{id}/video` | Исходный MOV; поддержка Range; ключ обязателен |
| `/api/v1/jobs/{id}/report?format=json` | Скачивание ответа API с кадрами |
| `/api/v1/jobs/{id}/report?format=html` | Автономный отчёт с кадрами; печать в PDF |
| `/api/v1/rules` | Каталог оснований с условиями и исключениями |

`limit` — от 1 до 100, `offset` — от 0. Времена метаданных — Unix seconds UTC.
Для незавершённого или ошибочного анализа отчёт возвращает 409. Неверный `format` — 422.
История отсортирована по времени загрузки от новых к старым; исходное имя — только для
интерфейса, не входной признак анализатора.

Браузер получает исходный MOV защищённым запросом и воспроизводит локальный Blob URL:
API-ключ не попадает в URL плеера, cookie или хранилище браузера. MOV-кодеки отличаются:
если браузер не воспроизводит выбранный кодек, это отдельно показывается и не подменяет
результат серверного декодирования.

## Сроки, очередь, хранение

Отсчёт бюджета начинается при поступлении POST, до чтения его тела. Watchdog отмечает
просроченные задачи как `failed / deadline_exceeded`, а поздний ответ модели уже не может
переписать ошибку. Watchdog не убивает зависшую GPU-операцию: `/readyz` сообщает
`analyzer_stalled`, новые загрузки получают 503 до возврата потока или перезапуска.

Завершённые задачи, результаты и исходные файлы удаляются через `FCM_RETENTION_HOURS`
(по умолчанию 24 часа; проверка примерно раз в минуту). Активный файл работающей модели
не удаляется. Скачанные на клиент отчёты этим механизмом не управляются.

Известные ошибки анализа: `invalid_video`, `unsupported_codec`, `deadline_exceeded`,
`analysis_failed`, `service_restarted`. Ни одна не содержит итоговый verdict.
